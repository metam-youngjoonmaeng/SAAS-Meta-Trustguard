### Pentagon 5축 설계

컬렉션관리부 9개 항목·4개 대분류를 그대로 반영한 Pentagon 5축의 정의·매핑·산식입니다. 소비자보호부는 Pentagon 을 사용하지 않습니다 (20항목 Y/N + 12 AI 카테고리 기반).

#### 설계 배경

초기 베이스 대시보드(01-QA_Dashboard / 02-hanwha-QA_Dashboard)는 Pentagon 5축
(`오프닝 및 목적 안내 / 설명 명확성 / 준수·고지 품질 / 대화·경청 품질 / 발화 안정성`) 을 그대로 상속했었습니다.
이 5축은 TM 판매 콜 평가표 기준이라 컬렉션관리부의 9개 평가항목·4개 대분류와 직접 매핑되지 않으므로,
컬렉션관리부 평가 흐름(기본 절차 준수 / 화법·음성 안정성 / 경청·공감·대안 제시 / 정확한 처리 / 사후 등록)에 맞춰 재설계했습니다.

#### 5축 정의 (SSOT)

| item_type_no | RADAR_KEYS (코드)     | RADAR_LABELS (표시명) | 카테고리 | 9 항목 매핑 (order_no) |
| ------------ | --------------------- | --------------------- | -------- | ---------------------- |
| 1            | `greeting_verify`     | 인사·본인확인          | 친절도   | 1, 2, 3                |
| 2            | `tone_language`       | 응대 화법·음성         | 친절도   | 4, 5                   |
| 3            | `empathy_listening`   | 경청·공감 응대         | 맞춤 응대 스킬 | 6, 7              |
| 4            | `work_accuracy`       | 업무 정확도            | 업무 정확도 | 8                   |
| 5            | `aftercare`           | 사후 처리              | 사후 처리 | 9                     |
| 99           | (summary)             | summary               | -        | 종합의견                |

> 모든 9개 항목이 정확히 1개 축에 배치되며 누락·중복 없음.

#### 축 점수 산식

각 축의 점수는 **해당 축에 매핑된 항목들의 `획득점수 합 / 만점 합` 의 백분율** 입니다.

```
axis_score = round1( 100 × Σ(earned_i) / Σ(max_pts_i) )    (i ∈ axis 매핑 항목)
```

- `max_pts_i` = `qa_checklist_rows.validation_time` 의 `"배점 N"` 에서 N 추출. 직무(PDS1/PDS2/PDS3/수동대인/인바운드) 별 만점 매트릭스 사용 (`DB_SCHEMA.md` 4-1 참조).
- `earned_i` = `qa_evaluation_rows.manual_eval` (수기 보정 후), 미수기 시 `ai_eval`.
- 단일 항목 축(④/⑤)은 항목 자체의 100점 환산 백분율과 같습니다.

##### 직무평균 / 전체평균

- `team_avg[axis]` (UI 라벨: **직무평균**) = 같은 직무(role) + 같은 부서 내 최근 N건의 axis 점수 평균.
  본 PoC는 직무별 만점 매트릭스가 다르므로 비교 baseline 단위도 직무(`PDS1` / `PDS2` / `PDS3` / `수동대인` / `인바운드`).
- `overall_avg[axis]` (UI 라벨: **전체평균**) = 전체 컬렉션관리부 콜의 axis 점수 평균.
- 시드 mock 에서는 `agent_score` 에 일정 buffer 를 더해 시각적 비교가 가능하도록 채움.

> 📌 API 응답 키는 호환을 위해 `team_avg` 그대로 유지. UI 표시 라벨만 "직무평균" 으로 렌더링.

#### 등급(rating) 룰

`qa_analysis_report.rating` 은 콜의 axis_score 구간에 따라 다음 라벨을 사용합니다 (정량 시각화 SSOT — 의미/방향성 라벨 부여 금지).

| axis_score | rating |
| ---------- | ------ |
| 90~100     | 우수   |
| 80~89      | 보통   |
| 70~79      | 주의   |
| 0~69       | 실패   |

`item_type_no = 99` (summary) 행은 `rating = NULL`.

> 📌 `qa_analysis_report` 의 `item_type_no` 1~5 / 99 는 컬렉션관리부 콜에서만 채워집니다. `item_type` 컬럼 값은 위 5축 정의의 RADAR_LABELS 와 정확히 일치해야 호버 리포트가 매칭됩니다.

## 소비자보호부 평가항목

### POC 개요

고객사에서 제공한 POC 안내 문서를 기반으로 한 핵심 정의입니다.


| 항목       | 내용                                          |
| -------- | ------------------------------------------- |
| 평가 단위    | 콜 1건마다 평가 (회원-상담사 통화 1건 = 평가 1건)            |
| 평가 기준 양식 | 5개 시트(평가기준 / 금칙어 / 유형분류 / 결과양식 등)로 분리되어 제공됨 |
| 결과 산출물   | 시트 2-x 형식의 평가/분석 결과 출력물                     |


소비자보호부는 다음 두 트랙으로 구성됩니다.

1. **평가 트랙** — 평가항목별 Y/N 채점 (감점 방식)
2. **AI 분석 트랙** — 금칙어 감지 + 콘텐츠 유형 분류 + AI 분석 대상 자동 선정

> ⚠️ 직무 구분: 소비자보호부는 직무 분리 없이 **단일 ("전체")**. 컬렉션관리부의 직무별 가중 배점 개념은 적용되지 않습니다.

#### 분류 결과 출력 포맷

각 통화별로 위 12개 분류에 대한 **적합도 점수(0~100)**가 산출됩니다.

> 📌 **적합도 점수의 성격**
>
> - **평가/감점 점수가 아님** — 통화 내용이 해당 유형 카테고리에 얼마나 부합하는지를 AI가 산출한 **계량화 지표**
> - 용도: **향후 통계/트렌드 분석 활용** (예: 법적 리스크 70점 이상 콜의 비중 추이)
> - 예시: `1. 리스크 관리 / A. 법적 리스크 감지 / 70점`
>
> 📌 **다중 분류 가능** — 하나의 콜이 여러 유형(예: 법적 리스크 + 설명 부족)에 동시에 해당될 수 있음. 법적 리스크가 있는 콜이 동시에 불성실 답변·회피 상황도 보일 수 있다는 점에서, UI는 다중 분류 결과를 모두 노출해야 합니다.
>
> 📌 분류 체계는 **향후 확장 예정** (POC 시점 기준 12개 소분류, 추후 추가/세분화 가능성 있음).

#### 적합도 점수 표시 설계 (POC 기본값)

화면 구현을 위한 정량 기준입니다. 고객사 가이드 수령 시 조정 가능.

##### 점수 구간 (4단계, 정량 기준)

카테고리의 긍정/부정 의미는 부여하지 않습니다. 모든 카테고리에 동일하게 **점수 자체**에 따라 농도/강도만 다르게 표시합니다.


| 구간     | 라벨  | UI 처리   |
| ------ | --- | ------- |
| 80–100 | 높음  | 진한 단일 색 |
| 60–79  | 중간  | 보통 농도   |
| 30–59  | 낮음  | 옅은 농도   |
| 0–29   | 없음  | 회색      |


##### "해당됨" 임계값: **60점**

- 60점 미만은 막대그래프에만 표시되고 요약 카드에는 노출 X
- 60점 이상은 요약 카드에 노출

##### 화면 표시 방식

모든 카테고리는 **동일한 단일 색상(예: 브랜드 메인 컬러)** 의 **농도 차이**만으로 구분합니다. 카테고리 자체에 색을 부여하지 않습니다.

```
┌───── AI 유형 분류 적합도 ──────────────────────┐
│ 60점 이상 해당: 2건                            │
│ ┌────────────────────────────────────────────┐ │
│ │ 1. 리스크 관리 / A. 법적 리스크 감지        │ │
│ │ ████████████████░░░░  70점 (중간)           │ │
│ └────────────────────────────────────────────┘ │
│ ┌────────────────────────────────────────────┐ │
│ │ 2. 품질 관리 / B. 설명 부족                 │ │
│ │ █████████████░░░░░░░  60점 (중간)           │ │
│ └────────────────────────────────────────────┘ │
│                                                │
│ [▾ 전체 12개 카테고리 점수 보기]                │
│ (펼치면 12개 막대 모두 표시, 60 미만은 회색)    │
└────────────────────────────────────────────────┘
```

##### 정렬 우선순위

1. 점수 높은 순
2. 동점일 경우 대분류 번호 순 (1 → 2 → 3 → 4)

## 평가체계 버전 관리

평가항목(체크리스트·Pentagon 축)의 추가·삭제·의미 변경이 발생할 때, 과거 콜 데이터의 일관성을 보장하면서 신규 콜에 새 정의를 적용하기 위한 버전 관리 체계입니다.

### 설계 원칙

#### 원칙 1. 콜 데이터는 frozen snapshot

- `qa_checklist_rows` / `qa_evaluation_rows` / `qa_consumer_eval_rows` 의 `category` / `item` / `item_text` / `validation_time` 등은 콜 row 안에 박혀 저장됨 (현 스키마에 이미 보장됨).
- 마스터(`eval_item_defs`)가 바뀌어도 과거 콜의 표시 라벨·배점은 그대로.
- 평가항목 관리에서의 어떤 수정도 과거 콜 row 를 소급 수정하지 않음.

#### 원칙 2. 변경의 4가지 유형

편집 모달에서 변경 종류를 구분하여 처리.


| 변경 유형                       | 버전 영향          | 효과                                                          |
| --------------------------- | -------------- | ----------------------------------------------------------- |
| ① 텍스트 다듬기 (오탈자, 표현 정리)      | ❌ 같은 버전 in-place | `criterion` / `prompt_template` 등 텍스트 필드 갱신, `updated_at` 만 변동 |
| ② 배점 변경 (점수제 만점 조정)          | ❌ 같은 버전 in-place | `validation_time` 기준값 변경, 집계 차트에 변경 시점 마커만 표시              |
| ③ 의미 변경 (사실상 다른 항목으로 갈아끼움)   | ✅ 새 버전 발행      | 구 항목 비활성, 신규 항목 발행으로 분리                                    |
| ④ 항목 추가 / 삭제                  | ✅ 새 버전 발행      | 추가: `effective_from` 시점 / 삭제: `deactivated_at` 시점          |


- 모달에 라디오 두 개로 노출: ○ 텍스트 다듬기 (과거 통계와 합산)  ○ 의미 변경 (별도 항목으로 분리)
- 배점 변경(②)은 채점방식 자체가 바뀌는 게 아니므로 in-place 로 두되, 시각적 마커로만 통지

#### 원칙 3. 버전 단위 = 부서별

- 컬렉션관리부 / 소비자보호부 각각 독립적으로 `v1`, `v2`, `v3` ...
- 콜은 단일 부서에 속하므로 콜→버전 매핑이 1:1 (`qa_calls.CDATE` ↔ `effective_from` range 매칭)
- 항목별 버전, 평가체계 전체 단일 버전은 채택 안 함 (전자는 콜이 다중 버전이 되어 표시 불가, 후자는 한 부서 변경이 다른 부서로 전파됨)

#### 원칙 4. 채점방식은 부서 속성, 항목 단위 토글 불가

- 컬렉션관리부 = 점수제, 소비자보호부 = Y/N 으로 DB 가 강제 (`qa_consumer_eval_rows.yn CHECK IN ('Y','N')`).
- [`src/pages/EvalItems.jsx`](../src/pages/EvalItems.jsx) 의 채점방식 라디오는 부서 컨텍스트에 따라 자동 고정·disabled 처리.
- 부서 단위 채점방식 전환은 PoC 범위 외 (필요 시 별도 마이그레이션 화면).

### 발행 방식 — A안 (자동 발행)

- 편집 모달의 **"의미 변경" 라디오를 체크한 상태로 저장 → 즉시 `v(n+1)` 발행**.
- 텍스트 다듬기·배점 변경은 같은 버전 안에서 in-place 갱신.
- 항목 추가/삭제는 자동으로 새 버전 발행.
- 발행 시점의 `effective_from` 기본값은 `now()`. 모달의 "효력 발생 시점" 필드로 미래 시점 (예: 익일 자정) 으로 미룰 수 있음.

> 운영 단계에서 변경 빈도가 늘어나면 "드래프트 + 일괄 발행 (B안)" 으로 확장.

### 버전 라벨 표기

`v{n} · {effective_from}~` 형식.

```
평가체계 ▾
─────────────────────────────
전체 (기본)
─────────────────────────────
v3 · 2026-05-15~ (현재)
v2 · 2026-03-01 ~ 2026-05-15
v1 · ~ 2026-03-01
```

- `effective_from` 은 효력 시작일 (발행일이 아님 — 발행 후 미래 시점으로 미룬 경우 효력일 기준)
- 가장 최근 활성 버전에는 `(현재)` 마커
- `effective_from` 이 미래인 경우 `(예정)` 마커

### 홈 화면 "평가체계" 필터

[`src/pages/Dashboard.jsx`](../src/pages/Dashboard.jsx) 의 기존 "평가" 슬롯을 재활용하고, 라벨을 `평가체계` 로 변경.

#### 기본 동작: "전체"

- 구/신 콜이 한 화면에 혼재 — 시간축 차트에 변경 시점 vertical 마커 표시
- 의미 변경(③)된 항목은 항목별 분포 차트에서 `(구) 라벨` / `(신) 라벨` 로 분리해 같은 화면에 노출
- 배점 변경(②)은 분리 없이 같은 라인, 변경 시점 마커만

#### 버전 선택 동작 — 부분 겹침 / 완전 벗어남

| 사용자 선택            | 날짜 범위                       | 동작                                                     |
| ----------------- | --------------------------- | ------------------------------------------------------ |
| 전체 (기본)            | 임의                          | 구/신 통합 뷰, 변경 시점 마커                                    |
| v2 (2~5월 효력)       | 2~3월 (완전 안쪽)               | 그대로 표시                                                 |
| v2 (2~5월 효력)       | 1~3월 (부분 겹침)               | 2~3월만 표시 + 배너 "선택 범위 중 1월은 v2 효력 이전 (0건)"             |
| v2 (2~5월 효력)       | 1월만 (완전 벗어남)              | 자동 전환 → v1 + 배너 "날짜 변경에 따라 v2 → v1 자동 적용됨"            |


- **자동 전환은 0건이 될 때만** — 부분 겹침은 사용자 의도 존중하고 부분만 표시
- 자동 전환 시 반드시 배너로 명시 + "전체 보기" 출구 버튼
- 빈 화면 표시는 채택 안 함 (사용자가 버그로 오인할 가능성)

### 점수 표시 — 백분율 정규화

배점 변경(②)에 강건하도록 집계 화면의 점수는 백분율 위주로 표시.

- Pentagon 축 산식 `100 × Σ(earned)/Σ(max)` 는 이미 백분율 ([축 점수 산식](#축-점수-산식) 참조)
- 홈 화면 총점 표시도 백분율 기본, 절대값 (예: `65/86`) 은 콜 상세에서만 보조 표시

### DB 스키마 확장 (제안)

[`docker/init/postgres/07_eval_item_defs.sql`](../docker/init/postgres/07_eval_item_defs.sql) 에 다음 컬럼·제약 추가 필요.

```sql
ALTER TABLE public.eval_item_defs
  ADD COLUMN department      text NOT NULL DEFAULT '컬렉션관리부'
    CHECK (department IN ('컬렉션관리부', '소비자보호부')),
  ADD COLUMN version         integer NOT NULL DEFAULT 1,
  ADD COLUMN effective_from  timestamptz NOT NULL DEFAULT now(),
  ADD COLUMN deactivated_at  timestamptz NULL;

ALTER TABLE public.eval_item_defs
  DROP CONSTRAINT eval_item_defs_org_order_uk,
  ADD CONSTRAINT eval_item_defs_versioned_uk
    UNIQUE (org_id, department, order_no, version);

CREATE INDEX IF NOT EXISTS idx_eval_item_defs_effective
  ON public.eval_item_defs (org_id, department, effective_from DESC);
```

- 콜 row 에는 별도 `version` 컬럼 추가하지 않음. `qa_calls.CDATE` ↔ `eval_item_defs.effective_from` range 매칭으로 derive.
- 부서별 버전은 해당 부서 항목들의 가장 최근 발행 시점을 대표 버전 번호로 사용.

### 콜 → 버전 매핑 쿼리

```sql
SELECT version
  FROM public.eval_item_defs
 WHERE org_id     = :org
   AND department = :dept
   AND order_no   = :order_no
   AND effective_from <= :call_cdate
   AND (deactivated_at IS NULL OR :call_cdate < deactivated_at)
 ORDER BY effective_from DESC
 LIMIT 1;
```

부서 단위 대표 버전이 필요한 경우 (예: 평가체계 필터 드롭다운 옵션 생성):

```sql
SELECT DISTINCT department, version, MIN(effective_from) AS effective_from
  FROM public.eval_item_defs
 WHERE org_id = :org
 GROUP BY department, version
 ORDER BY department, version DESC;
```

## 화면 구성 방향

POC 안내 문서 + 평가 체계 분석 결과로 도출된 화면 구성 방향입니다.

### 부서/직무 데이터 모델

```
call: {
  ...
  department: '컬렉션관리부' | '소비자보호부',
  role: 'PDS1' | 'PDS2' | 'PDS3' | '수동대인' | '인바운드' | '전체'
}
```

- `department === '컬렉션관리부'` → `role`은 5개 직무 중 하나
- `department === '소비자보호부'` → `role`은 항상 `'전체'`

### 통화 상세 화면 분기


| 부서     | 좌측 영역                               | 우측 영역                                                  |
| ------ | ----------------------------------- | ------------------------------------------------------ |
| 컬렉션관리부 | 9개 평가항목 체크리스트 (직무별 만점 자동 적용)        | Pentagon Diagram + 코멘트 + STT 토글                        |
| 소비자보호부 | 평가 트랙 (20 항목 Y/N, 위반 시 -1점, 만점 20점) | AI 분석 트랙 (금칙어 감지 / 유형분류 적합도 / 분석대상 O·X) + 코멘트 + STT 토글 |


#### 소비자보호부 점수 표시 원칙


| 영역        | 표시 방식                                                             |
| --------- | ----------------------------------------------------------------- |
| 평가 점수     | `**총점 / 만점` + 위반 항목 수** (예: `17/20 · 미충족 3건`)                     |
| 금칙어 감지    | **여부/갯수만 표시** (점수화 X) — Level별 색상 + 감지된 단어 리스트                    |
| 유형 분류 적합도 | **0~100 적합도 점수** — 평가 점수와 별개의 통계 지표임을 명시 (예: 막대그래프 + "통계용 지표" 라벨) |
| AI 분석대상   | **O / X 뱃지 + 사유** (점수화 X)                                         |


### 소비자보호부 화면의 조건부 렌더링


| 조건          | UI 동작                                    |
| ----------- | ---------------------------------------- |
| AI 분석대상 = O | 평가 트랙 + AI 분석 트랙 모두 활성                   |
| AI 분석대상 = X | 평가 트랙만 활성, AI 분석 트랙은 "분석 미수행" 표시 + 사유 노출 |


### 통화 목록 화면 추가 사항


| 추가 컬럼/필터         | 설명                             |
| ---------------- | ------------------------------ |
| 부서 컬럼            | 컬렉션관리부 / 소비자보호부                |
| 직무 컬럼            | 컬렉션관리부 통화는 5종, 소비자보호부 통화는 "전체" |
| AI 분석대상 컬럼       | O / X (소비자보호부 전용)              |

| 부서 필터            | 부서 드롭다운                        |
| AI 분석대상 필터       | O / X / 전체                     |
