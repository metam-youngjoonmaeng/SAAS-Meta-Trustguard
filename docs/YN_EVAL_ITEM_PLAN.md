# Y/N 평가항목 기획서 — 컴플라이언스 체크리스트

> 05-Meta-Trustguard 평가항목의 Y/N(yes_no) 처리 방식 설계
> 작성일 2026-06-25 · 상태: **기획 확정 단계(미착수)** · 코드/DB 변경 없음

---

## 1. 개요 (TL;DR)

- Y/N(yes_no)은 **점수가 아니라 "확인용 체크리스트"** 다. 콜의 품질 점수(점수제)와는 **완전히 분리**된 별개 차원으로 둔다.
- 측정하는 것: "**했나 / 안 했나**" — 필수 안내멘트, 금칙어, 본인확인 등 **이행/위반 여부**.
- 핵심 산출물: **항목별 이행률·위반율 모니터링** + **위반 콜 드릴다운(민감건 감지)**. 관리자는 누락/위반 난 것만 골라서 **예외 관리**한다.
- Y/N은 **콜 점수(점수제 총점)와 펜타곤에 일절 영향 없음.** 별도 "컴플라이언스" 화면에서 비율로만 관리.
- 따라서 점수 합산 로직 변경은 "**yes_no 항목을 합산/펜타곤에서 제외**"가 전부 → 단순하고 무회귀.

## 2. 배경 — 현재 구현 상태 (코드 기준)

| 단계 | 현재 동작 | 위치 |
|---|---|---|

| 루브릭 변환 | Y/N → `allowed_steps=[max,0]` 이진, `scoring_type:'yes_no'` 플래그로 엔진에 전달 | `server/rubricSync.mjs:220-242` |

**실측(2026-06-25)**: 활성 평가항목 전부 numeric, **yes_no 0개**(미사용 기능).

### 2.1 문제점
1. **잘못된 위치** — Y/N이 점수 합산에 끼어들어 "1점짜리 점수항목"이 됨. 본질(이행/위반 체크)과 안 맞음.
2. **모니터링 부재** — "필수멘트 누락률 12%" 같은 **항목별 이행률 집계 화면이 없음.** ← 정작 필요한 기능.
3. **민감건 추적 불가** — "금칙어 발생 콜"을 따로 모아 보는 동선이 없음.
4. **표시 미분화** — 결과에서 `0/1`로만 보여 위반 여부가 안 보임.

## 3. 핵심 결정 — Y/N = 컴플라이언스 체크(점수 완전 분리)

점수제와 **역할 자체가 다른 별개 차원**으로 정의한다.

| | 점수제(numeric) | Y/N(체크리스트) |
|---|---|---|
| 측정 | 콜의 **품질 점수** (얼마나 잘했나) | 특정 행동 **이행/위반** (했나 안 했나) |
| 결과값 | 0 ~ 만점 (연속) | 충족(Y) / 미충족(N) / 해당없음(N/A) |
| 항목 예 | 응대 태도, 설명력, 해결력 | 필수 안내멘트 누락, 금칙어 사용, 본인확인 실시 |
| 관리자 관점 | 콜별/상담사별 **점수** | **항목별 이행률·위반율** |
| 관리 방식 | 점수 높낮이 | **예외 관리** (위반/누락 난 것만) |
| 콜 총점 영향 | 있음 | **없음** |
| 펜타곤 영향 | 있음 | **없음** |

> **결정(2026-06-25)**: Y/N은 콜 점수에 **일절 영향 없음**(완전 분리, 순수 모니터링).

## 4. 상세 설계

### 4.1 콜별 Y/N 결과 (3-state)

- 각 콜 × Y/N 항목 → **충족(Y) / 미충족(N) / 해당없음(N/A)**.
- 저장: 기존 `qa_evaluation_rows` 재사용 (충족=배점, 미충족=0). **단, 이 order_no는 점수 합산에서 제외.**
- **해당없음(N/A)** 처리: 항목이 그 콜에 적용 안 되는 경우(예: 인바운드 전용 멘트를 아웃바운드 콜에서). 비율 계산 시 **분모에서 제외**해야 정확. → 엔진이 N/A를 명시(권장) 또는 "행 없음/판정불가"를 N/A로 간주. *(소결정 ①)*

### 4.2 점수/펜타곤에서 제외 (핵심 변경)

- 합산부에서 **`scoring_type='yes_no'` order_no를 `sumEarned/sumMax`에 누적하지 않음** (`qaPipelineIngest.mjs`, ICS 경로 `index.js`).
- 펜타곤 축 계산(`buildPentagonByAxisDefs`/`orderNoPct`)에서도 yes_no order_no 제외.
- 결과: 점수제 점수·펜타곤은 Y/N 도입과 **무관하게 그대로** 유지(무회귀).

### 4.3 집계 뷰 — 핵심 기능 ⭐

**항목별 이행률/위반율 대시보드:**
- 지표: 항목별 `미충족(또는 위반) 건수 / 해당 콜수 = 위반율(누락율)`.
- 필터: **기간 · 상담사 · 브랜드 · 도메인 · 부서 · 채널(io_divi)**.
- 표현: 항목 리스트 + 위반율 막대/숫자, 추세(기간별), 임계 초과 시 강조(*소결정 ②*).
- 데이터 출처: `qa_evaluation_rows` ⨝ `eval_item_defs`(scoring_type='yes_no') ⨝ `qa_calls`(상담사·기간·채널 필터).

### 4.4 위반 콜 드릴다운 — 민감건 감지

- 집계 화면에서 항목 클릭 → "금칙어 발생 콜 8건" 식의 **위반 콜 리스트** → 콜 상세로 이동.
- 민감 항목(예: 금칙어)은 별도 강조/배지로 빠르게 식별.

### 4.5 화면(UI)

- **평가항목 편집기**(`EvalItems.jsx`, `DomainEvalPage.jsx`): Y/N 항목은 "**체크 항목**"으로 정의(이름·확인기준·프롬프트). 만점/배점 입력 불필요(점수 무관). "충족=1 자동" 문구 제거.
- **결과 화면**(`Detail.jsx`): Y/N은 **점수 항목표와 분리된 "컴플라이언스 체크" 섹션**에 `✓ 충족 / ✗ 위반 / – 해당없음`으로 표시(점수 미표기).
- **신규 컴플라이언스 대시보드/탭**: 4.3 집계 + 4.4 드릴다운. (메뉴 위치 *소결정 ③*)
- **펜타곤**: Y/N 미포함(점수 아니므로).

### 4.6 평가엔진(맹주임) 협의

- 엔진은 지금처럼 Y/N 항목을 **충족/미충족 판정** (`scoring_type='yes_no'`).
- 협의 1건: **해당없음(N/A)** 판정을 명시적으로 반환할지(예: `score=null` + judgment='해당없음'). → 비율 분모 정확도에 직결. 미지원이면 대시보드가 "판정불가=N/A"로 간주.
- 점수 가산 의미가 없으므로 엔진 입장에선 부담 거의 없음.
- (향후 옵션) 금칙어처럼 결정적 항목은 LLM 대신 **키워드/룰 기반 체크**도 가능 — 별도 검토.

## 6. 구현 순서 (작게·수시 커밋)

1. **점수/펜타곤 제외** — 합산·펜타곤에서 yes_no order_no 제외 (`qaPipelineIngest.mjs`, `index.js`). 무회귀.
2. **콜별 결과 표시** — `Detail.jsx`에 컴플라이언스 체크 섹션(충족/위반/N/A).
3. **집계 API** — 항목별 위반율 쿼리 + 필터(`server` 라우트).
4. **컴플라이언스 대시보드** — 집계 화면 + 위반 콜 드릴다운(`frontend`).
5. **편집기 정리** — Y/N 항목 정의 UI(점수 입력 제거).
6. **엔진 N/A 협의 반영**(맹주임) + 샘플 체크 항목 시드.

> 각 단계 standing 룰대로 **배포 → 테스트 → 이상 없으면 commit & push**.

## 7. 무회귀 / 엣지케이스

- **무회귀**: 현재 yes_no 0개 → 점수/펜타곤 제외 로직을 넣어도 기존 점수제 동작 완전 불변.
- N/A 분모 제외 누락 시 위반율이 낮게 왜곡 → N/A 처리 확정 필요(*소결정 ①*).
- 상담사/기간 필터 시 표본 적은 항목은 비율 신뢰도 낮음 → 표본수 함께 표기 권장.
